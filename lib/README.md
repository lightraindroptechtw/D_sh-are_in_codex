# D_sh-are_in_codex 技術說明

本文件說明目前來源的共同處理方式及其界線，與 [相容性說明](../COMPATIBILITY.md) 一起閱讀。以下參照本機 CC 的 `README.md` 和 `lib/claude-host/README.md` 的使用流程、多入口、設定表達式及 `dsh` 命令說明；Codex 的宿主與介面不同，不表示兩邊所有程式或行為相同。

## 依指定清單清理宿主

本輪只核對 CC 清理清單中的宿主、登記表、狀態、套件及文件。保留 Codex 專用入口、服務和狀態定位，不將 CC 的死碼刪除直接套用到 Codex。服務註冊函式新增與 CC 相同用途的失敗隔離；停用掛鉤時不再編譯掛鉤，模板快取區分是否包含掛鉤。相關 12 項測試全部通過，包括合成產物的實際啟動與呼叫。細節及未搬入項目見 [指定清單核對](../verification/cleanup-2026-10-29/CC指定清單核對.md)。

## 來源、設定與執行

轉換前先固定來源並掃描；掃描不執行插件。使用者看過結果並同意後才轉換安裝。安裝成功、工具可列出、實際呼叫成功與完整工作流程成功是不同的驗證結果。

一個 `cordis.patch.yml` 可列出多個插件入口；轉換計畫保留各入口與設定，由宿主分別載入。`!!js` 設定採受限表達式解析，不使用 `eval`（動態執行字串）；可讀取明確傳入的環境變數名稱，不把值寫進轉換報告。超出支援語法的表達式不執行。實際支援範圍以 `compat/dsh-expression.mjs` 為準。

## MCP 與 Python

正式宣告的 MCP（工具連接協定）伺服器沿用原宣告處理；是否能啟動仍取決於設定、依賴、權限與實際環境。Python 原始碼掃描只列候選，不再以字面 `.run(transport="stdio")` 篩選；它不證明候選的啟動命令、傳輸方式、依賴或已掛載。原有 `requirements.txt` 依賴準備保留，不從 `pyproject.toml` 推定依賴，也不自動掛載掃描候選。

不再依 `dshBin`、`pythonPath`、`cfgFile`、`configFile`、`DSH_HOME`、`serverName`、Python 環境變數或工具裝飾器等來源名稱，推定插件私有設定、路徑、工具清單與服務；也不再自動寫入推定的狀態設定或建立由該推定產生的 MCP 設定。插件自帶安裝器不變；例如 `bili_setup` 需使用者自行操作，本輪未實際執行。

## 通用命令轉接與 Codex 差異

保留通用的假 `dsh` 命令，將受支援的呼叫轉接到 Codex 工作端點。`overlay`（覆蓋設定）只接受實作明確支援的資料形式；不支援內容會報錯，不能推論所有 DSH 覆蓋設定都適用。CC 技術說明中以 Claude 子代理處理的細節，不能直接當作 Codex 的實作。這條轉接也不會因 Python 候選被掃描到，就自動替插件猜出 MCP 連線。

與 CC 一樣，沒有接入的臨時 MCP 服務會明確告知，任務繼續使用目前已有工具；通知、回傳結果與命令的錯誤輸出會指出缺少的服務，並讓子代理知道不可假稱執行成功。不會由來源檔名、變數、工具裝飾器或私人狀態檔推導臨時服務。若宿主明確提供正式工具轉接器，仍可使用；原有的指令格式、設定資料及權限驗證不因此取消。

通用命令目前已測試 Node 直接使用 `spawn`、`spawnSync`、`execFile`、`execFileSync` 呼叫裸名稱 `dsh`／`dsh.cmd`／`dsh.exe` 的轉接。經過殼層字串、任意絕對路徑或其他語言啟動的呼叫，不在這次已驗證範圍內。
