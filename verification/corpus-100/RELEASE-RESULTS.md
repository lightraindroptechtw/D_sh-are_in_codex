# 0.3.0 交付與 Luna 獨立驗證

日期：2026-10-23（台北）。Windows、Node.js 24.16.0、Codex CLI 0.160.0。測試工作由 Luna 子代理獨立執行；主代理修正共通實作並核對實際安裝副本。

## 改善的實際行為

- 原插件以 setTimeout（延後執行）註冊工具時，自動使用官方宿主，後續工具可更新到同一條 MCP（工具連接協定）連線並成功呼叫。
- 工具白名單含未知名稱時，靜態報告會標明未確認；純工具引擎清楚拒絕啟動，官方引擎狀態會列出尚未註冊的名稱。清單外的來源工具仍不公開。
- packageDir 可選程式庫內的套件，保留整個來源根目錄、上層共用資源及套件工作目錄，拒絕越界入口。
- 使用真正官方技能服務列出及讀取動態技能，保留相對資源位置；拒絕只供人使用的技能。原 CDP 插件的 browser-cdp 技能及未連線路由已實測。
- 批次轉換共用已編譯的宿主程式，本輪 77 次重用、1 次建立。每個輸出仍複製獨立的固定依賴；未量測速度倍率。

生成包內附官方執行套件，不必安裝或開啟 DSH 主程式。來源自己呼叫 dsh 命令、外部程式、模型或依賴完整 DSH 代理與會話時，仍不能直接等同相容。

13 次功能呼叫並非 13 個插件，也不是全部 100 件都啟動。安裝副本重測的是同一個 finance ratio 分支，不額外計入 13 次。舊 24 來源的歷史結果在上層 expansion 目錄，不與本次新來源重複計數。

8 次失敗來自 finance、education、translation 原回傳含 undefined（未定義值），官方無損 JSON（資料交換格式）驗證拒絕。另 4 次 verify config 呼叫的回傳含 summary.format/depth/note，與來源宣告的輸出規格衝突。來源未改寫，驗證沒有關閉；結論限於本版固定官方執行套件，沒有在 DSH 主程式另跑對照組。

81/100 是結構產生比例，不能當成功能相容率。converted 也不等同所有功能可用；partial 仍含未保留或未確認部分。原介面、完整代理與會話迴圈、模型接管、完整背景工作語意仍需個別移植。

## 來源與重現界線

100 個套件皆固定精確 npm 發佈封存、版本及 SHA-256（內容雜湊），不是 Git 最新提交。套件、封存內容、解壓樹及實作內容各 100 個互異；同一程式庫的三個獨立套件造成程式庫總數為 98。依類別配額與固定排序選樣，非隨機抽樣。GitHub 的 fork（另行開發的複本）關係因限流未完整查核。詳見 [來源稽核](audit-summary.json) 與 [來源收集報告](collection-report.md)。

批次是在版本號尚為 0.2.1、共通修正已完成後執行。釋出前核對所有 lib 與 bin 檔案內容，均與批次結束雜湊相同；版本號改為 0.3.0。完整 104 項測試則在 0.3.0 下執行。比對見 [釋出內容雜湊](release-implementation-hashes.json)。

本壓縮包附全部測試結果與 100 份轉換報告，不附 100 份第三方原始封存或生成包；固定下載網址在 candidates.json，本次解壓來源和產物留在工作區 work/dsh-corpus-100 與 work/dsh-luna-validation-100-v0.2.1-20261023-run2。drivers/ 保存本次實際驅動程式，其相對路徑依賴原工作區布局，並非解壓即重下載的安裝腳本。

來源批次沒有執行初始化或安裝來源依賴。功能測試只啟動經審查的四個來源、使用合成資料及獨立狀態；未登入、發送訊息、呼叫模型或執行網路工具分支。Codex 解析使用隔離設定，沒有安裝或啟動 81 個插件。Codex 啟動時一筆背景精選插件快取請求收到 401，解析本身仍全通過。

可重新執行本包的程式與整合測試：

```powershell
$env:CODEX_INTEGRATION='1'
npm test
```

其中固定來源的整合案例需要工作區原有的來源目錄；另行解壓到沒有語料的位置時，相關案例可能跳過，不能把跳過算成通過。子程序隔離不是作業系統的檔案或網路沙箱。
