# 0.9.2：補上 CC 的另外兩個 DSH 指令

本次對照本機 CC 的 skills/scan/SKILL.md 與 skills/install/SKILL.md，補上 Codex 原生技能：

| 指令 | 用途 |
|---|---|
| `$dsh-to-codex:scan <來源>` | 下載固定來源並掃描，由目前對話審查，不安裝 |
| `$dsh-to-codex:install <來源>` | 使用者看過結果並同意後，轉換安裝同一固定來源 |

接受 npm 套件名稱及版本、公開 GitHub 網址、本機資料夾。GitHub 子套件可另指定資料夾。來源審查、同意與安裝不依賴市場清單；服務重啟後仍能沿用簽署保存的來源。來源被改動則不能安裝。混淆程式的強制安裝必須另外明確選擇，不由一般安裝同意推定。

## 真正執行的驗證

- Codex 0.160.0 的 plugin/read 實際辨識四個技能，其中包括新增的 scan、install 與原有開市場技能。繁體中文選單名稱也已辨識。詳見 native-skills.json。
- 兩個自己建立的合成插件，在隔離的 Codex 設定與市場資料夾真正安裝，Codex 列表確認已安裝且啟用。分別走只看固定掃描，以及提交主對話審查的路徑。
- 兩者安裝後都用 verify_codex_plugin 明確執行來源並呼叫 echo，取得預期文字。這證明轉換後工具能執行；沒有驗證由主對話模型選擇並派發工具。詳見 native-direct-commands.json。
- 使用者未同意時不安裝。安裝回報保留 toolsVerified:false，與後續真正呼叫的證據分開。
- 已安裝到使用者的插件版本為 0.9.2；新程序的 open_dsh_market 已啟動 0.9.2 並回報排入 Codex 瀏覽器開啟要求。本輪沒有額外做畫面檢查，不把 queued 說成畫面已顯示。詳見 native-upgrade.json。

## 測試結果與範圍

完整測試 464 項，463 通過、1 項在測試後刪除 Windows 暫存資料夾時遇到 EBUSY（資料夾仍被占用），0 跳過。該項功能在單獨重跑時通過；測試清理增加短暫重試後，同檔 2 項再次通過。完整紀錄 full-tests.log 與最終重跑 host-recheck.log 均保留，沒有把重跑冒稱完整測試一次全過。

較早一輪另找到技能選單資料漏檔及舊工具清單斷言未更新，均已修正；受影響的 8 項通過，之後的完整測試也通過這兩項。

新增回歸包含：固定版本不重抓新版、來源被竄改、明確同意、服務重啟、GitHub 子目錄、混淆強制選項，以及大量固定掃描結果不流入主對話。以 4,000 個各 800 字的標記及 20 萬字文件驗證：待選範圍回傳少於 6,000 字；正常代表片段回傳少於 12,000 字；完成審查也不回傳整份掃描。

閒置舊版服務自動更新只對同一 Codex 設定與同一安裝來源生效，工作執行中會請稍後再試。資格判斷已有測試；本輪實際開啟回傳 restartedForUpgrade:false，因此沒有把舊版正在運作時的替換稱為已實測。

未呼叫額外模型、第三方 API，也沒有實際發文。本輪沒有重新抽樣真實第三方插件，不將兩個合成插件推論為全部社群插件皆能運作。
