# 0.5.0 模組對應表

## 社群市場入口與本機頁面

0.5.0 新增的市場是本插件內附的本機瀏覽器頁面，與下方轉換來源所需的 DSH 服務模組分開。它不修改 Codex 原生插件頁，也不表示已支援 DSH 原生畫面。使用 Node.js 22.19.0 以上，在根目錄雙擊 `開啟DSH插件市場.cmd` 或 `.vbs`，或執行 `node ./bin/dsh-to-codex.mjs market --open`，即可讓人直接操作。

| 入口或操作 | 行為與邊界 |
|---|---|
| `open_dsh_market` | 第 4 個 MCP 工具；只開啟頁面，不準備或安裝插件 |
| 市場清單 | 切換兩個內附社群索引，提供搜尋、分類與分頁；第三方文字作資料展示 |
| 「了解插件」 | 顯示用途、來源、作者與版本等資訊；來源宣稱不等於功能驗證 |
| 「準備安裝」 | 下載固定版本、分析及轉換；正式依賴安裝停用腳本，不初始化來源 |
| 「確認安裝到這台電腦」 | 使用者看過結果後才登記生成包；完成後須新開 Codex 聊天 |

人類市場流程不需要 AI 操作，不呼叫模型、付費推論服務或登入。取得遠端 Git 來源需 Git；確認安裝需可使用的 `codex` 命令。索引與 npm 來源有大小限制；Git 傳輸有逾時限制，目前沒有位元組數硬上限。是否可執行仍依每個來源的轉換報告與功能實測判定，0.5.0 最終驗證結果由 [VERIFICATION.md](VERIFICATION.md) 彙整。

## 沿用的來源服務模組

0.4.1 增補：明確設定的已知模組也會參與選擇，明確 `modules` 清單仍優先。網頁模組可選擇掛載 `nativeFetch.allowedOrigins`，實作官方抓取來源介面；預設停用，逐次檢查網站範圍與重新導向，限制文字大小、取消與逾時，不提供搜尋或瀏覽器渲染。用法見 [README](README.md)。

工具執行的工作目錄與連線識別在同一宿主程序內穩定；每次呼叫的核准仍獨立。`exec.agent.session.append` 僅支援自訂插件紀錄，以官方分離對話的紀錄格式檢查後寫入獨立本機檔；拒絕原生代理／對話事件，不寫入 Codex 聊天。專注筆記的設定、讀取、附加、摘要、封存與清除已有功能證據；這不擴大下表對原生 DSH 對話操作的支援。

原生 Node 子程序的依賴由管理的預載入器解析，官方套件固定到內附版本；不改寫來源或其依賴目錄。`allowUndeclaredOutput` 是明確的輸出相容選項，預設關閉。詳見 [0.4.1 測試報告](verification/v0.4.1/RELEASE-RESULTS.md)。

每個來源的 conversion-report.json 列出選中的模組、版本與能力檢查、逐方法對應。下列逐方法程度對應 lib/modules/ 的模組宣告：完整表示保留該方法在表列範圍內的行為，部分表示只有明示的對應，不支援表示沒有可用的對應。這不代表所有來源插件已啟動或功能成功，也不換算成主觀百分比。

MCP 是工具連接協定；API 是程式呼叫介面；app-server 是 Codex 應用服務；hooks 是事件掛鉤。表內方法、能力標籤與設定欄位保留程式原名，說明使用繁體中文；能力標籤未必是可直接呼叫的來源函式名稱。最低版本是本模組宣告的需求；不依賴 Codex 特有介面的原生服務，沒有另外宣告最低版本。能力檢查通過不等於已取得使用者信任或外部服務授權。

## 代理與對話模組（agents）

DSH 服務：agents。最低 Codex：0.160.0。所需能力：Codex 應用服務。

| 方法或能力 | 程度 | 邊界 |
|---|---|---|
| create | 部分 | 建立由本模組管理的 Codex 對話；須明確允許模型呼叫並指定可用模型，只轉入建立階段的靜態提示內容。 |
| resume | 部分 | 只續用明確允許的 Codex 對話識別碼；不重播 DSH 事件，也不在宿主重啟後重建原有代理別名。 |
| list | 部分 | 只列出本模組建立或續用、目前仍存活的代理；不列舉桌面應用中的其他聊天。 |
| get | 部分 | 只查找本模組目前管理的存活代理。 |
| agent.send | 部分 | 只接受文字；閒置時開始新回合，執行中則引導目前回合。不實作 DSH 收件匣排隊或送入但不喚醒的行為。 |
| agent.whenIdle | 部分 | 等待本模組所管理的 Codex 回合結束；回合失敗或中斷會回報錯誤。 |
| agent.cancel | 部分 | 中斷本模組的進行中回合；不重播或還原 DSH 收件匣。 |
| handle.dispose | 部分 | 中斷並收束進行中的工作，移除本模組的代理控制物件；保留 Codex 對話歷史。 |
| setup | 部分 | 只把不含動態插值的 systemPrompt.section 靜態文字轉成建立對話時的開發者指示；掛入工具、代理預設或修改服務作用域會明確失敗。 |
| session.append | 部分 | 只對應 approval/policy 中的 never（不要求核准）與 on-request（按需要詢問），套用到後續回合；其他事件寫入或修改會失敗。 |
| agent/pre-step | 不支援 | Codex 沒有提供 DSH 每一步執行前的准入介面，無法逐步攔截完整代理迴圈。 |
| register | 不支援 | 不能用外部 DSH 代理實作取代 Codex 的執行流程。 |
| setFactory | 不支援 | 不支援替換 Codex 的內部代理迴圈。 |

使用條件：

- 建立、續用對話或送入模型回合前，必須明確設定 allowModelCalls=true；預設不允許模型呼叫。
- 必須指定 Codex model/list（可用模型清單）實際列出的模型；來源模型無對照時明確拒絕，不默換供應商或模型。
- 本模組不會自行啟動背景宿主；來源設定 never（不要求核准）時會另列警告。

- 必須另外掛載相容的供應商轉接器；本模組不自動安裝轉接器，也不登入服務。

| start | 部分 | 使用者明確執行 daemon start（啟動背景宿主）後，獨立背景程序維持官方計時器與插件服務 |
| stop | 完整 | 經驗證的本機控制端點停止程序 |
| schedule | 部分 | 沿用官方 timer；程序或電腦關閉期間不會執行，沒有補跑保證 |
| automaticStartup | 不支援 | 不自動啟動背景程序或設定開機工作 |

使用條件：

- 必須明確啟動；呼叫模型另需 allowModelCalls 與模型對照設定。背景停止控制只停止背景宿主，不能用來關閉由 Codex 管理的 MCP 宿主。

## 共通限制

- 保留來源與官方套件原文，不為特定插件名稱寫分支。缺失能力只停用對應模組，提供明確錯誤；若來源初始化本身無法處理這項缺失，它仍可能無法啟動。
- 官方工具與設定在工作程序內運作；程序隔離並非檔案與網路沙箱。
- API 金鑰模式須明確啟用 allowModelCalls、允許的模型路由及來源供應商轉接器。沒有替使用者建立 API 金鑰，沒有用付費模型做測試。
- Codex 無工具短對話的假說未採用：現有介面無法保證所有工具關閉。
- 第5節 installed-dsh 是規劃的選擇性項目，本版未實作；模組化引擎不必安裝 DSH 主程式。
