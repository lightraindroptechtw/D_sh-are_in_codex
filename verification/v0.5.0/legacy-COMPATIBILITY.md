# 0.5.0 相容性與驗證範圍

## 0.5.0 人類操作的社群市場

本版內附本機瀏覽器頁面，提供兩個社群索引的來源切換、搜尋、分類、分頁、插件介紹與指定版本安裝流程。它不是 Codex 原生插件頁的修改，也不是把 DSH 原生畫面移植進 Codex。使用者可雙擊根目錄的 `開啟DSH插件市場.cmd` 或 `.vbs`，全程直接操作，不需要 AI。

「準備安裝」下載固定來源版本、分析並轉換，預設連線安裝正式依賴且停用安裝腳本；不初始化來源。「確認安裝到這台電腦」在使用者看過結果後才登記生成的 Codex 插件，新開 Codex 聊天後載入。`open_dsh_market` 僅開啟頁面，不安裝插件。最低需要 Node.js 22.19.0；遠端 Git 來源與安裝分別需要 Git 與可使用的 `codex` 命令。

市場標題、描述、作者、分類與版本是第三方資料。支援顯示與下載不能證明來源宣稱的用途正確，也不能證明插件所有功能相容；準備結果須保留可用、略過及未確認內容。市場頁面與轉換流程不呼叫 AI／模型或付費推論服務，不登入、不對外發送內容；連線讀取來源及本機安裝是流程明示的行為。索引與 npm 來源設有大小上限；Git 傳輸有逾時限制，目前沒有位元組數硬上限。

0.5.0 整合模式 241 項測試全部通過，市場頁面完成真正安裝；已安裝的配速插件通過三個計算案例。這次沒有重跑整個第三方語料庫，詳見 [本版驗證](VERIFICATION.md) 與 [交付報告](verification/v0.5.0/RELEASE-RESULTS.md)。

## 0.4.1 已驗證功能與沿用限制

0.4.1 已補上真正功能驗證。原本學術寫作、教育、翻譯與驗證四個來源，在明確啟用兩項輸出相容選項後通過 11 個內容案例；財務插件的私有修正副本通過 60 個案例；瀏覽器驗證完成成功與故障偵測兩例；網頁分析完成真正本機 HTTP 抓取及內容分析。最新逐來源結果見 [0.4.1 報告](verification/v0.4.1/RELEASE-RESULTS.md)。以下舊 100 來源數字維持 0.4.0 的實測版本，不把新功能抽測當成全量重新啟動。

新增邊界：`allowUndeclaredOutput=false` 預設不變；只有明確開啟才放寬輸出結構對額外欄位的禁止，不改輸入或已宣告型別。宿主程序內共用連線識別；自訂插件事件有實際本機紀錄，但原生 DSH 代理生命週期與 Codex 聊天寫入仍不支援。明確設定 `moduleOptions.web.nativeFetch.allowedOrigins` 才提供限定網站的文字抓取，不提供搜尋或瀏覽器渲染。Node 子程序透過管理的預載入器解析來源依賴；需要 Node 22.19.0 以上，來源與官方套件不改寫。

0.4.0 以共通模組提供來源所需服務，逐方法支援程度見 [MODULES.md](MODULES.md)。`conversion-report.json` 的模組可用性是版本／能力檢查結果，不等於來源已初始化或工具已成功。缺能力只停用對應模組並報告；來源若在初始化時呼叫不支援的方法，仍可能無法啟動。混合插件的工具與服務須逐項分析，不能因為同時有畫面就整包排除。

## 版本範圍更正與目前驗證範圍

0.3.1 的「57 個至少一項官方版本不符」採用了未納入預發布版本的舊規則。以相同 100 來源及相同 0.3.1 內附環境，改用 `includePrerelease=true` 後更正為 26。這是較寬鬆的版本範圍判定，不是功能成功率；也不能將不同版本內附環境的數字直接比較。見 [更正說明](verification/v0.4.0/analysis-corrections.md) 與 [逐項資料](verification/v0.4.0/range-correction.json)。

最終[一般測試](verification/v0.4.0/final-default.log)共 201 項，196 通過、5 跳過、0 失敗；[整合測試](verification/v0.4.0/final-integration.log)為 201 項全部通過。內附官方 SDK（軟體開發套件）共 34 個，[純匯入檢查](verification/v0.4.0/official-sdk-import-final.json)為 34／34 通過；[複製後環境測試](tests/v040-runtime-environment.test.mjs)確認所有官方 SDK 的匯入都來自複製的執行環境，且未執行安裝腳本。這只證明套件解析與匯入，不代表已建立服務或驗證全部方法。

初輪 0.4.0 批次與失敗原因記錄在 [claude-review.md](verification/v0.4.0/claude-review.md)。該輪包含已辨認的分析／登記表、套件解析與來源入口問題。[目前 100 來源彙整](verification/v0.4.0/batch-report.md)以 `final2` 完整 100 筆為基準，再以最後補齊依賴後的 `peerfix` 32 來源子集覆蓋相應結果，其餘 68 筆保留 `final2` 實測；不是全部 100 來源在最後環境重跑。[逐筆 JSON](verification/v0.4.0/batch-report.json)的 `provenance`（證據來源）記錄各來源的批次、實作雜湊與產物路徑，原始兩輪報告也分別保留。

來源批次關閉掛鉤。[Codex 解析證據](verification/v0.4.0/codex-read.md)已核對最新 90 個生成產物的識別碼及完整路徑，90／90 成功；其中最後替換的 31 個另行解析，59 個沿用 `final2` 既有證據。合成插件的 10 個掛鉤全部被列出，警告與錯誤均為 0；掛鉤仍未受信任、未由 Codex 實際執行。真使用者核准互動也未驗收。

驗證須分列：生成包結構、MCP 初始化、來源工具列舉、至少一個安全工具呼叫。找不到安全項目或本來未生成服務者標為不適用，不當成失敗或成功。登入、發送內容、模型推論與付費服務不作批次驗證附帶行為。生成、解析、列工具都不能單獨證明功能可用。

## 歷史附錄：0.3.1 相容性調查

以下保留各版本當時的規則、數字與測試範圍；其中「不安裝來源依賴」「掛鉤選填」與代理能力限制等敘述不能作為 0.4.0 現況。0.4.0 行為以上方說明及逐模組報告為準。

本次調查把 DSH 主程式專屬介面、完整代理/會話流程，和可獨立執行的工具/服務分開。前兩者不要求自動重建；混合插件不能因為包含介面就整包排除。

已確認三個轉換器缺口並修正：來源宣告的官方依賴版本未核對、大於 512 KiB 的程式檔被略過，以及技能名稱必須等於資料夾名的過嚴判定。詳見 [0.3.1 調查報告](verification/investigation-031/REPORT.md)。下方 0.3.0 數字是修正前的歷史證據。

0.3.1 當時對相同 100 來源再次做純分析，87 個找到可轉換介面，新增辨識的 4 個都是較大的發佈入口；這仍不是功能成功率。當時舊規則記為 57 個套件至少一項官方依賴宣告不符；0.4.0 已在相同環境重算更正為 26，原始 57 僅保留作歷史。`runtimeCompatibility` 保留逐項範圍、實際版本與判定。

## 0.3.0 歷史證據

不必安裝或開啟 DSH 主程式；生成的插件內附固定版本的官方執行套件。若原插件另外啟動 `dsh` 命令、外部程式或模型，仍需另外移植或提供那些能力。

本版新增共通能力：原服務的動態技能讀取、延後工具註冊、未知工具白名單診斷、子目錄套件與上層資源保留，以及同一程序內重用宿主編譯結果。每個生成包仍有自己的依賴。原工具政策與輸出驗證照常執行，不以清除錯誤回傳值來換取通過。

Luna 子代理測試了額外 100 個社群套件，來自 98 個程式庫，與舊 24 來源的程式庫不重複。這是按功能類別配額、固定排序選樣；不是隨機抽樣，也不是官方認證。100 個套件名稱、封存雜湊、解壓內容雜湊及實作內容雜湊各自唯一；GitHub 的分支來源關係未完整查核，不能宣稱排除了所有 fork（複製後另行開發的程式庫）。

| 新增測試層級 | 結果與限制 |
|---|---|
| 來源分析與轉換 | 100 份報告；2 個 converted、79 個 partial、19 個 unsupported，沒有未預期拋錯 |
| 產物結構 | 81 個生成包全部通過；17 個在現有規則下未找到可轉換介面，2 個因來源技能名稱與目錄不符被驗證器拒絕 |
| 初始化與功能 | 另見 verification/corpus-100 的實測報告；批次轉換本身沒有執行任何來源 |
| 未支援部分 | DSH 聊天介面、完整代理及會話迴圈、模型接管、完整背景工作語意仍需個別移植 |

`partial` 表示仍有未保留或未確認的部分，不是完整相容。`converted` 也只代表生成結果沒有列出省略項目，不能代替實測。19 個 unsupported 的逐項原因保存在 verification/corpus-100/unsupported-details.json；不能只因同時出現 NATIVE_UI 診斷，就推論該插件全部只是介面功能。

CDP 插件的原始 `browser-cdp` 動態技能已經由真正的官方技能服務列出並讀取，未連線狀態路由也回傳成功；本次沒有連接或操作瀏覽器。舊版下表的動態技能限制已由此項測試更新。

## 0.2.1 歷史證據

本版以結構選擇執行方式，程式內沒有以插件名稱判斷如何移植。純工具沿用可攜工具引擎；需要宿主服務的來源，使用固定版本官方 DSH/Cordis（插件執行環境）。原始碼保持原狀，工具呼叫經真正的 DSH 前置、執行及後置政策。程序隔離不是檔案或網路沙箱。

24 個真實來源中，21 個產生了結構合法的插件包。這個數字不代表 21 個插件的所有功能都相容。Codex 本身成功解析全部 21 個產物，並同時載入 3 個純工具插件、3 個官方宿主插件及轉換器，共 36 個工具項目。
