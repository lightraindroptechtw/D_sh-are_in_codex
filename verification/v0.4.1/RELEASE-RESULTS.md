# DSH 轉 Codex 0.4.1 交付與功能結果

日期：2026-10-23（台北）。這次處理的是實際工具呼叫與內容結果，並更新可安裝的轉換器。原始 100 來源語料與官方 DSH 套件未修改。

## 已修正與實測

| 項目 | 修正與結果 |
|---|---|
| 原本四個失敗來源 | 學術寫作、教育、翻譯、驗證插件，使用 0.4.1 新生成包通過 11／11 個內容案例：引用格式、文字檢查、成績統計、試題有效性、文字切分、數字／括號核對、正確與錯誤 JSON 檢查。這不是模型翻譯或教學內容生成的驗證。 |
| 輸出相容 | 明確開啟 `lenientOutput` 及 `allowUndeclaredOutput`，修正未定義欄位與額外輸出欄位造成的拒絕。保留實際 `summary.format`、`summary.depth` 等資料，已宣告欄位的型別、必填、列舉值及輸入驗證仍生效；預設兩者皆關閉。 |
| 財務插件本身 | 在獨立私有副本修正百分比放大、小數千分位、動態資產名稱、現值與再平衡訂單、零波動結果、組合報酬與中位數判斷。嚴格模式 30／30、寬鬆模式 30／30；原版 10／32 的失敗結果保留，不挪用副本成績。 |
| 跨次讀寫 | 工具在同一宿主程序共用穩定識別及工作目錄；逐次核准獨立。專注板完成設定、讀取、附加、摘要、封存與清除；實際本機插件事件紀錄存在且識別一致。 |
| 非同步登記 | 修正初始化回覆前收到工具登記通知時遺失工具的競態。文獻搜尋、詳情、引用格式、書目格式與合成筆記共 5 例通過。 |
| 子程序依賴 | 管理的 Node 預載入器讓原生 ESM（模組載入格式）及 CommonJS（另一種模組格式）子程序找到來源依賴，官方套件仍固定到內附版本。未改寫來源目錄。瀏覽器驗證實際完成按鈕點擊、文字檢查與故障偵測兩例。 |
| 網頁分析 | 明確掛載限定網站的 HTTP（網頁傳輸協定）文字抓取來源，逐次檢查重新導向、文字類型、大小、取消及逾時。實際來源完成本機網頁標題、正文、標題層級、連結、統計與關鍵字分析，九項內容檢查通過。無系統命令替代路徑。 |

財務副本與原授權在 [repairs/finance-data](../../repairs/finance-data)，[差異檔](finance-source-repair.patch)可直接審查。沒有在共通轉換器加入插件名稱分支。上述輸出相容與模組設定均記錄於每個生成包，不把放寬後的成功稱為原始輸出宣告通過。

實測環境為 Windows、Node v24.16.0、Codex 0.160.0。0.4.1 的執行需求為 Node 22.19.0 以上；沒有宣稱在所有 Node 或作業系統版本都測過。

交付前另核對全部 161 個鎖定依賴的 Node 版本宣告：內附 `undici@8.11.2` 的最低需求是 22.19.0，比解析掛鉤本身所需的 22.15.0 更高，因此同步修正了套件引擎宣告及文件。功能實測後未改執行程式；各次實測保留原始雜湊，不把這項中繼資料調整藏進既有證據，見 [版本需求核對](runtime-requirements.json)。

## 證據範圍與使用

四個來源、財務副本、網頁分析及瀏覽器有 0.4.1 重測。A／B 組的其他功能證據保留各自實測的版本與雜湊；23 個來源是所列功能成功，不代表這些插件的全部功能成功，也不是最後版本重新執行整個 100 來源批次。舊版初始化結果仍見 [0.4.0 批次報告](../v0.4.0/batch-report.md)。

可用的生成包路徑、明確設定及逐案例結果見 [四個來源](four-functional.json)、[財務](finance-repair.json)、[網頁分析](scrape-functional.json)、[瀏覽器](browser-package-041.json)。瀏覽器實測使用新生成包及隔離 Chromium（瀏覽器）檔案，Playwright 的瀏覽器檔案需要另外具備；本轉換器交付壓縮包不內附該瀏覽器。測試只使用合成網頁，不讀取瀏覽器登入資料。

同一宿主內的本機插件紀錄不等於原生 DSH 代理生命週期；不把事件寫進 Codex 聊天，不補跑模型回合或通知。網頁抓取不提供搜尋、登入、網頁程式渲染或圖片下載。DSH 原生聊天畫面、側欄及完整代理步驟仍不支援。

這次所有測試沒有登入、模型／付費服務呼叫、對外訊息或使用者文件寫入。已安裝轉換器需要新的 Codex 對話載入；目前聊天中已存在的舊工具連線不會因此自動重啟。測試用生成插件未全部安裝到使用者設定。
