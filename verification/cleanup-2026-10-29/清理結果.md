## 與 CC、DSH 對照的範圍

唯讀參考本機 CC 的 README.md、lib/claude-host/README.md、lib/inspect.mjs 及 lib/claude-host/dsh-cli.mjs。CC 沒有本輪移除的私有狀態寫入和自動 Python 加掛路徑；這部分已清理。兩邊共同採固定來源、掃描、使用者決定、多入口與受限設定表達式；宿主啟動、命令、模型與代理仍使用各自平台實作，不能直接混用。

DSH 官方 `@deepseek-ai/dsh-mcp-client` 的連接設定包括 transport、serverName、command、args、env、cwd。此次讀取的連接實作把命令與參數交給 MCP 傳輸層；不能由此說成 DSH 會從 Python 原始碼或 pyproject.toml 自動準備環境。正式宣告的 Python MCP 保留原命令、參數與工作目錄，由 Codex 原生啟動，並通知沒有替它準備 Python 依賴，亦不受來源 Node 的資料夾限制。

與 CC 相同，未接入的臨時 MCP 不再造成整個文字任務直接失敗：通知缺少的服務，命令錯誤輸出與結果保留警告，子代理使用已有工具繼續，並明確知道不能聲稱已使用缺少的工具。Codex 既有支援的設定資料格式和權限驗證仍有平台差異；不是宣稱所有 DSH 覆蓋設定都能使用。

## 刷 B 站的影響

不再自動填入 dshBin、pythonPath 或改寫其私人 config.json；不再從它的程式文字推定、加掛 Python MCP。其內附 bili_setup 工具和設定頁安裝按鈕仍是原插件自己的實作，本輪未修改，也未實際執行。

來源顯示這兩個入口會由使用者操作觸發安裝，不是插件啟動就自動安裝。它會處理 uv、虛擬環境與 requirements；語音辨識另有安裝入口。這只證明它自己提供安裝流程，不證明 DSH 內建相同環境。移除特殊處理後的完整看影片、代理、留言與自動值班流程尚未重測；無法原樣接通的部分可依原始碼補寫。
